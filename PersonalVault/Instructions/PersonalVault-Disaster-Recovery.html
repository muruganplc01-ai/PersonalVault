Same person, same account, a different PC

Disaster recovery & accessing your vault from another computer

What to do if this PC dies, gets reimaged, or you simply want your vault on a second machine — a laptop and a desktop, for example. This is not the family/friend sharing flow — it's you, the same Google account, the same master secret, on a different piece of hardware.

The one thing that makes this possible

Google Drive sync is your backup. Every save uploads the encrypted vault.pvlt to your own Drive, and Drive keeps the last 5 revisions as a rolling history on top of that. If Drive sync was never turned on for this vault, there is nothing to recover — the vault only ever existed on the one machine that held it, and losing that machine means losing the vault, by design (there is no other backend, no password reset, no company that holds a copy).

💡 If you haven't connected Drive yet, do it now, before you need it — Sign in to Google Drive from the tray menu, or see PersonalVault-Drive-Setup-Guide.html in this same folder.

What you need before you start

  • Your master secret — there is no reset, so this only works if you still know it
  • The same Google account you originally connected Drive with
  • A copy of credentials.json (the same one this app already uses — see the note in step 2)
  • If two-factor authentication is on: either your phone with the authenticator app, or one of your 10 backup codes (see step 5)
1
New / other PC

Get the app onto the other machine

Either build a fresh portable copy there (see the publish script below) or copy over a publish\ folder you already built. No install, no admin rights — just an .exe.

2
Same folder as PersonalVault.exe

Bring your credentials.json along

Copy your existing credentials.json into the same folder as the .exe (or straight into the app's data folder). This is your own copy of the same file already sitting on your original machine — it identifies the app to Google, not you, so there's nothing new to create.

3
The Google sign-in prompt

Sign in with the same Google account

Launch the app and click Yes when asked to connect Google Drive. It has to be the same account as before — the app can only see files it created itself (Drive's narrow drive.file scope), so a different account won't find anything.

4
Automatic

Restore prompt appears — enter your existing master secret

Because this PC has no local vault yet, the app finds the one on Drive and asks: "Restore it here? You'll need the master secret it was created with." Enter your existing master secret (not a new one) and the vault decrypts, saves a local copy on this PC, and you're in.

⚠️ Wrong secret just shows "Incorrect secret" and lets you retry — there's no lockout counter, but also no hint and no reset. If you're genuinely not sure of it, stop and think before guessing repeatedly.
5
Only if two-factor authentication is on

Second factor: use a backup code, then re-set-up TOTP here

The authenticator app secret (TOTP) is deliberately stored per-machine and does not travel with the vault — this new PC won't recognize your phone's 6-digit code yet. The app will say "No authenticator is set up on this PC — use a backup code instead."

  1. Enter one of the 10 backup codes you saved when you first turned TOTP on. It's consumed immediately (one-time use).
  2. Once unlocked, go to Profile → Two-Factor Authentication... and set up TOTP fresh on this machine — a new secret, scanned/typed into your authenticator app again, confirmed with a live code.
✉️ Email MFA has no such step — it emails a fresh code on every unlock attempt regardless of which machine you're on, so it works immediately here with nothing extra to configure.
🔒 Out of backup codes and no access to the authenticator app that generated them? There is no other way in — same as forgetting the master secret, this is intentional. Keep the backup codes somewhere durable (not only on the phone that also runs the authenticator app).

Using two machines at once, going forward

Nothing stops you from keeping the app installed on both a desktop and a laptop permanently, both signed into the same account, both using the same master secret — that's exactly what this guide sets up. The one thing to know: there's no real-time merge between them. If you edit on both at close to the same time and both save, whichever save reaches Drive last wins — Drive's 5-revision history is your safety net if that ever clobbers something, but it isn't automatic conflict resolution. In practice, just treat "the one you have open right now" as the active copy.

Notes and troubleshooting

The things that actually come up doing this.
? I don't remember which Google account I used
Check drive.google.com on each Google account you might have used and look for a file named PersonalVaultData.pvlt — that's the one.
? I never turned on Drive sync — is there any other backup?
No. There is no cloud service, no account recovery, and no company holding a spare copy — that's the same zero-knowledge design that keeps your data private in the first place. Local-only vaults exist solely on the machine holding them.
? The app didn't offer to restore — it just started with an empty vault
Make sure you actually signed in with the account that has the Drive file, and that you're not still on an old cached sign-in for a different account. Sign out via the tray menu and sign in again with the right one if unsure.
? Do I need a new credentials.json for the new PC?
No — reuse the exact same one. It identifies the app to Google (the OAuth client), not this specific installation.
