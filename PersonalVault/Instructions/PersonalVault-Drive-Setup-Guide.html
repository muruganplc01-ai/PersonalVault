Set up your own Google Drive connection

A self-service guide for Personal Vault. Follow this on your own PC, signed in with your own Google account, and everything you create belongs to you alone — your own project, your own credential, your own bill (which will be $0).

Cost & ownership, up front

$0
No billing account or card required for this
~10 min
One-time setup, mostly clicking "Next"
Yours
You own this project — nobody else is responsible for it
1
console.cloud.google.com

Create your own project

Sign in with the Google account you want this vault tied to. Click the project switcher near the top-left (it may say "Select a project") → New Project. Name it anything, e.g. PersonalVault, and create it.

💳 You may see a banner offering "$300 in free credit" — that's an unrelated general Cloud trial. Dismiss it. Nothing here needs it or touches billing.
2
Search bar → "Google Drive API"

Enable the Drive API

With your new project selected, use the search bar at the top of the console to find Google Drive API, open it, and click Enable.

3
Google Auth Platform → Overview

Set up the consent screen

Google recently renamed this from "OAuth consent screen" to Google Auth Platform — same thing, new name. Click Get started and fill in:

  • App name — anything, e.g. Personal Vault
  • User support email — your own address
  • User type: External
  • Developer contact email — your own address again

Save through to the end of the wizard.

4
Google Auth Platform → Audience

Check the test users list

Open the Audience tab. Google often adds the account that created the project as a test user automatically — look for your own email already sitting in the Test users list. If it's there, you're done with this step.

⚠️ If you try to add yourself and get "Ineligible accounts not added": that's not a real error — it almost always means you're already on the list from step 3. Close the dialog and check the list before worrying about it.
5
Google Auth Platform → Clients

Create the OAuth client

Click Clients in the sidebar → + Create Client.

  • Application type — Desktop app (not Web application — this matters)
  • Name — anything, e.g. PersonalVault Desktop

Click Create, then Download JSON from the dialog that appears.

6
File Explorer

Place the file — this part is now automatic

Rename the downloaded file to exactly credentials.json, then drop it right next to PersonalVault.exe — that's the app's data folder by default (a PersonalVault folder created there automatically), whether you're running the portable build or one you built from source yourself.

✨ Personal Vault finds a credentials.json sitting next to its own .exe and copies it into its data folder for you on first launch — nothing to go find or type yourself.
📁 Changed the data folder already? If you've used Profile → Change Data Folder... to move it somewhere else, put credentials.json there instead — check Profile → Data folder for the current location, or Open Folder to jump straight to it.
7
PersonalVault.exe

Run it and connect

  1. Launch the app and choose your master secret (8+ characters, memorable, never shared with anyone — not even Google).
  2. When it asks "Connect Google Drive now?", click Yes.
  3. A browser window opens — sign in with the same Google account from step 1 and click Allow.
✓ Done when the tray shows "Signed in to Google Drive." Add an account entry and check drive.google.com for a new file named PersonalVaultData.pvlt — that's your encrypted vault, visible to no one but you.

Troubleshooting

The exact snags hit while writing this guide — in case you hit the same ones.
? Will I get charged for this?
No. Drive API usage is free for standard use, with a daily quota in the hundreds of millions of requests — a personal vault syncing one small file uses a sliver of that. No billing account is required to reach this point.
? "Ineligible accounts not added" when adding a test user
Almost always means that email is already listed (commonly your own, auto-added when the consent screen was created) — check the Test users list before assuming something's wrong.
? Where's my data folder?
By default, a PersonalVault folder created automatically right next to PersonalVault.exe — fully portable, nothing under %AppData%. Open Personal Vault → Profile... to see the exact path (and an Open Folder button), or to move it elsewhere with Change Data Folder....
? Sign-in fails or the app says credentials are missing
Double-check: the OAuth client was created as Desktop app, not Web application; the downloaded file was renamed to exactly credentials.json (not client_secret_....json); and it's sitting in the app's data folder — see Profile → Data folder above if you're not sure where that is.
? It's asking me to re-authorize / a new consent screen with more permissions appears
Only happens if you turn on Email two-factor authentication (Profile → Two-Factor Authentication...) — that method needs to send mail through your Google account, so it requests Gmail's send-only scope the first time you enable it, on top of the Drive scope this guide sets up. Nothing else in the app ever asks for more than Drive. If you'd rather not see that extra prompt at all, choose the Authenticator app (TOTP) method instead — it needs no additional Google permission and works fully offline.
? Can I delete this later?
Yes — it's entirely your own project. Delete or disable it anytime from console.cloud.google.com without affecting anyone else's vault.
